Platform-specific context handle required for discovery.

  • On Android, construct with the application Context: PrinterContext(applicationContext).

  • On iOS, no argument is needed: PrinterContext().

Discovery (mDNS + local-IP detection) needs Android system services; iOS gets the same info from POSIX getifaddrs + Foundation NSNetServiceBrowser without any handle.

actual class PrinterContext

iOS PrinterContext. Owns a shared CBCentralManager so peripheral identity survives across the scan → connect handoff: retrievePeripheralsWithIdentifiers(...) only returns peripherals the receiving CBCentralManager instance has previously discovered or connected. Two separately-constructed managers do not share that cache, so a peripheral the user just selected from a scan list cannot be retrieved by a fresh manager — connect() then throws "Peripheral not in CoreBluetooth cache". Holding one manager in PrinterContext eliminates that whole class of bug.

The library installs delegates ad-hoc: dev.printbeam.discovery.internal.bleScan swaps its scan delegate in for the lifetime of the scan, and BLE connection swaps its connection delegate in for the lifetime of open() … close(). Do not run a scan and a connect concurrently on the same PrinterContext — there is one delegate slot. The expected flow is scan → cancel the scan job → connect, which the demo's PrinterSetupViewModel does.

Parameters

externalCentralManager

Optional caller-owned CBCentralManager. Pass one only if your app already manages CoreBluetooth for unrelated reasons; sharing the instance avoids permission-prompt and state-change races. Default is to lazily construct one internally.
