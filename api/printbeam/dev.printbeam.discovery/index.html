expect class PrinterContext

Platform-specific context handle required for discovery.

actual class PrinterContext

iOS PrinterContext. Owns a shared CBCentralManager so peripheral identity survives across the scan → connect handoff: retrievePeripheralsWithIdentifiers(...) only returns peripherals the receiving CBCentralManager instance has previously discovered or connected. Two separately-constructed managers do not share that cache, so a peripheral the user just selected from a scan list cannot be retrieved by a fresh manager — connect() then throws "Peripheral not in CoreBluetooth cache". Holding one manager in PrinterContext eliminates that whole class of bug.
