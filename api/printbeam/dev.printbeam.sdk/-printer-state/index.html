PrinterState

sealed class PrinterState

Lifecycle of the session PrintBeam holds for one printer id, observable via PrintBeam.printerState.

Transitions are driven entirely by the facade: Connecting and Connected are entered by PrintBeam.connect and by the auto-connect / dead-link-reopen paths inside PrintBeam.print; Disconnected by PrintBeam.disconnect and PrintBeam.shutdown; Failed when an open or a write (after the single reopen retry) fails. Failed is a resting state — the next PrintBeam.connect or PrintBeam.print moves it back through Connecting.
