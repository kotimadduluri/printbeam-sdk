PrintBeam

object PrintBeam

Session-holding entry point over the PrintBeam engine — initialize / scan / connect / print / disconnect. Where the lower-level dev.printbeam.Printer opens and closes a connection per operation (a 1–3 s GATT handshake per receipt on BLE), PrintBeam holds one PrinterConnection per printer id across prints and reopens transparently when the link dies.

Printers are addressed by their stable string id (DiscoveredPrinter.id — derived from the endpoint, e.g. "net://192.168.1.100:9100" / "ble://AA:BB:CC:DD:EE:FF"). The registry is populated by scan (every found printer is registered automatically), by addManualPrinter, and by rememberPrinter. The id alone cannot be parsed back into an endpoint, so persisting just the id is not enough to survive a relaunch: persist the printer's endpoint and fields (or the values passed to addManualPrinter) and re-register on the next launch — both registration calls derive the same stable id every time.

Threading: suspend functions are main-safe — I/O runs on the SDK's internal dispatcher. Listener callbacks and callback-twin results are delivered on the main dispatcher. Concurrent prints to the same printer serialize; prints to different printers proceed in parallel.

Scan-vs-connect serialization is the facade's job: the iOS PrinterContext owns one shared CBCentralManager with a single delegate slot, so a BLE scan and a BLE connect must never run concurrently. Every connection-opening path (connect, the auto-connect and dead-link reopen inside print and queryStatus) therefore cancels any active scan before opening, and starting a new scan cancels the previous one.

Advanced integrations that need one-shot printing or custom transports use the L1 types (dev.printbeam.Printer, PrinterDiscoveryService) directly — this facade is built purely on their public seams and holds no privileged state. Status queries, however, should go through the facade's queryStatus: it reuses the held session, where the L1 dev.printbeam.Printer.queryStatus opens a second connection next to the one the facade already holds — on BLE a whole extra GATT handshake.

fun printerState(printerId: String): Flow<PrinterState>

Observe printerId's session lifecycle. The returned flow is StateFlow-backed: it replays the latest state immediately on collection and then emits on every change — but it conflates, so a collector observes the latest state, not necessarily every intermediate transition (a fast Connecting → Connected flip may arrive as Connected alone). Ids not (yet) registered read as PrinterState.Disconnected.

suspend fun queryDeviceInfo(printerId: String): DeviceInfo

Query printerId's identity over the held session via ESC/POS GS I n — manufacturer, model, firmware, serial. Fields the printer ignores come back null; DeviceInfo.isEmpty is true when it ignored all four (typical for BLE printers). The main consumer use is naming printers the scan couldn't: a port-scan-only network printer has no mDNS name, but often answers GS I with its model.

suspend fun queryStatus(printerId: String): PrinterStatus?

Query real-time printer status (ESC/POS DLE EOT) over printerId's held session, auto-connecting (scan cancelled first, state via PrinterState.Connecting) when none is live — exactly like print. Serializes with prints to the same printer, so a status query never interleaves bytes with a receipt.

Callback twin of queryStatus: runs in the facade scope, delivers (status, null) on success — a null status meaning the printer sent no reply — or (null, failure) when the query failed, on the main dispatcher.

Register a printer object the consumer already holds — typically a scan result restored from persistence — and return its stable id. scan
Link copied to clipboard
fun scan(transports: Set<Transport>, timeoutMs: Long = DEFAULT_SCAN_TIMEOUT_MS, listener: ScanListener): ScanHandle

Start a streaming discovery scan. Every found printer is delivered to ScanListener.onPrinterFound (re-emitted with merged fields when a later source enriches an earlier observation) and simultaneously registered, so connect / print accept its id immediately — including mid-scan. Per-source failures arrive via ScanListener.onTransportFailed without stopping the other transports; ScanListener.onFinished delivers the final deduplicated snapshot. All callbacks are dispatched on the main dispatcher; a callback that throws is logged via PrintBeamConfig.logger and does not stop the scan.

shutdown
Link copied to clipboard
fun shutdown()

Tear the facade down: cancel any active scan and pending callback twins, close every held connection (best-effort, in the background), reset all observed states to PrinterState.Disconnected, and return to the uninitialized state so initialize may be called again. Idempotent — calling on an uninitialized facade is a no-op.
